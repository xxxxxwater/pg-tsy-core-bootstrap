# PG-TSY Core review and upgrade plan — 2026-09-29

## Baseline

The review baseline was `main@586fb1f7` (2026-09-27). Its primary `ci` and `postgres-fill-ledger` Actions runs were green. Review scope covered mode dispatch, startup gates, durable execution/reconciliation, venue adapters, observability/admin surfaces, Dream-RSI, CI and release documentation.

The project is materially beyond a prototype, but it is **not yet a three-venue unattended production release**. Research/Shadow remains the defensible release posture while paper/live acceptance is closed venue by venue.

## Next upgrade route

1. **Stale-feed and lease-theft fault injection are automated**: CI proves READY -> stale -> `SAFE_HOLD`, and separately proves a PostgreSQL holder/fencing-token takeover causes the old daemon heartbeat to detect fencing loss and terminate non-zero. Next add reconciliation-drift injection on the durable real-venue reconcile path.
2. Populate per-venue execution/latency, position and recent-order snapshots from the same authoritative sources used by Risk/OMS/Reconcile.
3. Make live policy `PositionView` reconciliation-backed for entry price, unrealized/peak return and filled-entry count. The fill ledger has price/quantity evidence, but do not enable this until Hyperliquid/IBKR fill ingestion is proven complete.
4. Complete Hyperliquid and IBKR paper/testnet fault matrices independently.
5. Keep Binance PM disabled until full market-data, execution, account-history/cursor, positions, fees and emergency recovery are implemented.
6. Close authenticated Telegram/operator emergency control and owned-only flatten.
7. Cut a new RC only from an exact green SHA with image digest, migrations, rollback and venue-specific signoff.

## Non-goals

This pass does not deploy to a production server, touch the existing Binance PM/Freqtrade production bot, enable live trading, or claim profitability/HFT acceptance.
