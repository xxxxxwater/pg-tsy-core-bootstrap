# PG-TSY Core v0.2.1-rc.1 — PureGamma RSS V4 / Coinbase Live Sidecar Preview

**Pre-release | October 23, 2026 | Experimental / NO-GO for unattended Coinbase real-money trading**

This release advances the independent RSS-driven research/operations sidecar and does **not** register Coinbase as a native venue in the Rust `pg-core` daemon. The existing Binance PM / Hyperliquid / IBKR source, TSY `shadow` runtime, and MLSD research artifacts remain separately scoped.

## Included

- **PureGamma RSS V4 compatibility:** read-only raw event ingestion, provenance checks and deduplicated event fingerprints; local LibreTranslate English-to-Chinese Telegram headlines remain a separate presentation layer.
- **Isolated Coinbase Advanced Trade experimental sidecar:** strict official SEC signal filter for BTC-USD; explicit `PG_LIVE_TRADING`, dedicated Coinbase Portfolio identity and capped order budget gates; guarded preview/client order ID and durable local intent states. **Installing or pulling the image does not arm it.**
- **Telegram monitor Hotfix 1.1:** per-minute RSS/TSY/sidecar probes, hourly heartbeat, three-consecutive-failure alerts, recovery notifications, durable Telegram retry metadata and explicit `not_armed` as an expected safe state.
- **InstaBox operational runbook:** in-place monitor-only update, snapshot and rollback, no edits to the TSY daemon or original RSS V4.
- **Quality evidence:** 16 Python sidecar tests verified in prior CI; this release workflow reruns tests and validates an unprivileged, credential-free image before registry push.

## Acceptance boundary — no production trading claim

The server's earlier Hotfix 1.1 operator log showed a delivered Telegram heartbeat, `Coinbase LIVE state=not_armed`, RSS healthy, and TSY `shadow` with 8/8 market-data feeds at that observation time. This is **not proof** of Coinbase order submission, fills/fees, native protective order acceptance, crash recovery or continuous uptime.

The standalone Python Coinbase sidecar is **not** the Rust `pg-risk → fenced journal → OMS → reconciliation` pipeline; Coinbase is not an enumerated native venue in `contracts/signal.v1.json`. Automatic real orders must remain disarmed until identity isolation, approved hard risk limits, post-fill/fee/protection reconciliation, fault-injection and explicit release signoff are achieved. News sentiment alone is not execution approval.

## Supply-chain/security

No Coinbase private keys, Telegram bot tokens, chat IDs, live database snapshots or `.env` files are included in source artifacts or GHCR layers. Images are tagged only with this **RC version**, not `latest`, to prevent an experimental distribution being mistaken for a stable live trader. GitHub Actions uses the repository `GITHUB_TOKEN` with scoped permissions for release and GHCR publishing.
