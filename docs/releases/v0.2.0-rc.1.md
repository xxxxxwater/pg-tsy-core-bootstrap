# PG-TSY Core v0.2.0-rc.1 — MLSD offline feature research preview

This prerelease adds a **separate, research-only** MLSD feature engineering layer to PG-TSY Core. It does **not** establish paper/live readiness, turn on real trading, deploy to a host, or change order routing. The previous [v0.1.0-rc.1](https://github.com/xxxxxwater/pg-tsy-core-bootstrap/releases/tag/v0.1.0-rc.1) remains unchanged.

## Added in this prerelease

- Pinned upstream **MLSD v0.2.1** at the exact source commit `85e356c1fb6703fef2b03ac0070c5e0659e8c671`.
- New offline `research/src/pg_tsy/ml/mlsd_features.py` bridge from **Polars market data** to structured MLSD windows and 28 engineered summary features (21 price log-return Series + 7 volume Bag features).
- `PurgedEventTimeSeriesSplit` using *actual label end timestamps* plus optional row gap, with training-only transformer fitting.
- Hard validation of strictly increasing UTC nanosecond timestamps, a single venue/asset per dataset, price/volume bounds, target integrity, and stable output features.
- Separate `train_features.parquet`/`train_targets.parquet` and `validation_features.parquet`/`validation_targets.parquet` per fold; the target labels are never joined into the input feature file.
- `manifest.json` with versioned schema, per-artifact SHA-256, dataset fingerprint, fold feature columns and source configuration.
- `pg-tsy-mlsd` CLI with credential-free `--smoke` and offline parquet ingestion/export.
- New non-root **Python-only GHCR container**, independent of the Rust `pg-core` image, and a dedicated GitHub Actions Python contract test suite.

## Pull and run the research Docker image

```bash
docker pull ghcr.io/xxxxxwater/pg-tsy-mlsd:v0.2.0-rc.1
docker run --rm ghcr.io/xxxxxwater/pg-tsy-mlsd:v0.2.0-rc.1
```

To export your own market data:

```bash
docker run --rm \
  -v "$PWD/input:/input:ro" -v "$PWD/output:/output" \
  ghcr.io/xxxxxwater/pg-tsy-mlsd:v0.2.0-rc.1 \
  --input /input/market.parquet --output /output/features-001 \
  --window 16 --splits 4 --gap 2
```

Volume mounts must be writable for the image's UID 10001 and contain no active trading account credentials. The command reads local Parquet files only and emits research artifacts. New GHCR packages may be private until package visibility is explicitly changed.

## Local Python research workflow

```bash
cd research
python -m pip install -e '.[dev,mlsd]'
python -m pytest -q tests/test_mlsd_features.py
pg-tsy-mlsd --smoke
```

The GitHub release includes the Python research wheel and sdist alongside GitHub's automatic source archives. This package is designed for development and offline evaluation, **not** the trading daemon.

## Safety boundary and important limitations

**Research proposes; Rust disposes.** This MLSD integration has no exchange API permissions and cannot publish live signals, clear SAFE_HOLD, bypass Rust Risk/OMS, flatten positions, or reconcile venue state. The existing `Dockerfile`, `docker-compose.yml` and `docker-compose.production.yml` are unchanged. No API keys are placed in GitHub Actions.

No ML backtest, profitable strategy, trade execution or readiness for Binance PM/Hyperliquid/IBKR has been established merely by these feature tests. Correctness depends on causal ingestion of the original upstream market data and externally generated labels. Real-money canary and unattended execution remain **NO-GO** until the separate venue-specific acceptance gates in [RELEASE_READINESS.md](https://github.com/xxxxxwater/pg-tsy-core-bootstrap/blob/main/docs/RELEASE_READINESS.md) have independent evidence and operator approval.

See [MLSD feature engineering architecture and input contract](https://github.com/xxxxxwater/pg-tsy-core-bootstrap/blob/main/docs/MLSD_FEATURE_ENGINEERING.md).
